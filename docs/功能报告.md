# BidRadar Agent 功能报告

## 1. 项目定位

BidRadar Agent 对应赛题 1《招投标信息聚合工具》。它的核心不是纯聊天，而是把一句自然语言问题转成可执行的信息聚合任务：

```text
自然语言问题
  -> 意图解析：关键词 / 地区 / 时间 / 频率
  -> Agent 计划：来源选择 / 搜索词 / 执行步骤
  -> 多来源采集：固定来源 + 全网搜索 + 登录态来源
  -> 清洗去重：过滤无效页、合并重复公告
  -> 风险识别：截止临近、附件缺失、变更澄清
  -> Word 报告：老板可读、带来源链接
  -> 定时任务：只推新增内容
```

## 2. Web 入口链路

主要入口在 `src/main/java/com/xfusion/bidaggregator/controller/HomeController.java`。

```java
@PostMapping(value = {"/api/query", "/api/agent/run"}, produces = MediaType.TEXT_HTML_VALUE)
public String query(@RequestParam String question, Model model, HttpSession session) {
    QueryResult result = aggregationService.execute(question);
    prepareForDisplay(result);
    session.setAttribute(LAST_RESULT, result);
    model.addAttribute("question", question);
    addDashboardState(model, result, null);
    return "index";
}
```

页面提交问题后，控制器只负责接收、展示和保存会话结果；真正业务编排在 `BidAggregationService`。

## 3. 业务编排链路

核心服务是 `src/main/java/com/xfusion/bidaggregator/service/BidAggregationService.java`。

```java
SearchIntent intent = intentParser.parse(question);
AgentModelResponse modelResponse = agentModelService.analyze(question, intent, sourceNames);
agentModelService.applyToIntent(modelResponse, intent);

AgentPlan plan = agentOrchestrator.createPlan(question, intent, crawlers, modelResponse);
HarvestResult harvest = sourceHarvestService.harvest(intent, plan, trace, itemBatchConsumer, cancelled);
CurationResult curation = resultCurationService.curate(intent, harvest.getRawItems(), trace);

result.setItems(new ArrayList<>(curation.getItems()));
result.setCandidateItems(new ArrayList<>(curation.getCandidateItems()));
```

这条链路的分工：

- `IntentParser` 保证无模型也能解析；
- `AgentModelService` 只增强理解，失败可降级；
- `AgentOrchestrator` 生成可解释执行计划；
- `SourceHarvestService` 调度多来源；
- `ResultCurationService` 统一清洗、去重、风险和增量；
- `WordReportService` 最后生成 Word。

## 4. 多来源采集链路

`SourceHarvestService` 会先做全网搜索，再逐个跑启用的固定来源。

```java
CrawlResult searchResult = webSearchService.discover(intent, plan.getSearchQueries());
statuses.add(searchResult.getStatus());
rawItems.addAll(searchResult.getItems());

for (SourceCrawler crawler : enabledCrawlers(intent)) {
    if (cancelled.getAsBoolean()) {
        break;
    }
    CrawlResult result = crawler.crawl(intent);
    statuses.add(result.getStatus());
    rawItems.addAll(result.getItems());
}
```

如果某个来源失败，失败会变成来源状态里的 warning，不会让整个查询失败。

## 5. 清洗、风险和增量链路

`ResultCurationService` 是评分点最集中的地方。

```java
List<BidItem> cleaned = new ArrayList<>(
        cleanerDeduplicator.cleanAndDeduplicate(rawItems, intent));
cleaned.forEach(riskAnalyzer::analyze);

int skipped = 0;
if (intent.getScheduleRule() != null) {
    skipped = historyService.filterAlreadySent(intent, cleaned);
}
return new CurationResult(cleaned, candidates, duplicateCount, skipped);
```

它解决三件事：

- 去掉登录页、导航页、弱相关页；
- 合并同一公告的多来源重复；
- 定时任务只保留未推送的新公告。

## 6. 本轮优化

- 删除 `SourceHarvestService` 中未被调用的无参 `enabledCrawlers()` 透传方法，减少服务表面积。
- 未改动抓取、清洗、报告、登录态和定时任务核心链路。
