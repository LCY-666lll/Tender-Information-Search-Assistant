# 赛题 1：招投标信息聚合工具

## 题目目标

实现一个可运行的招投标信息聚合工具，支持用户输入自然语言问题后，自动解析查询意图，抓取招投标网站信息，清洗、去重、汇总后生成 Word 文件。

系统呈现形式可为 API、CLI 或 Web UI。当前默认路线为 Java / Spring Boot / Maven，优先做轻量 Web UI 方便录屏演示。

## 输入

用户输入自然语言问题，内容可能包含：

- 关键词：如服务器、充电桩、软件等。
- 区域：如安徽省、上海、北京等。
- 时间范围：如最近 1 个月、2026 年 3 月、最近 3 个月等。
- 频率或发送时间：如每天 9:00、今天 9:00、每周等。

示例：

```text
最近1个月安徽省区域内的服务器招标信息都有哪些。
2026年3月份上海区域内的充电桩招标信息有哪些。
最近3个月上海区域内的充电桩招标信息都有哪些，请汇总后每天9:00发送给我。
2026年4月份北京充电桩相关的招标信息都有哪些。
```

## 输出

每个问题生成 1 个 Word 文件：

```text
{用户的问题}_{时间}.docx
```

Word 内容必须包含：

- 标题。
- 发布时间。
- 来源链接。
- 核心内容。
- 附件链接，如有。
- 风险预警或洞察，如投标截止时间过近、附件缺失需人工复核。

如果用户要求定时触发，后续生成内容只包含新增信息，避免重复推送。

## 核心功能要求

- 自然语言意图解析：关键词、区域、时间范围、频率。
- 多网站抓取：信息来源至少 3 个，评分表中至少 2 个稳定来源可拿满多站点抓取分。
- 登录态抓取：至少 1 个需要登录后获取信息的网站；仅使用免费会员可见内容，不绕过登录或访问控制。
- 内容清洗：去除导航、广告、模板噪声，过滤不满足条件的内容。
- 去重：处理转载、镜像、跨站同步造成的重复。
- 汇总：字段结构化后生成 Word。
- 定时与增量：支持每日/每周等定时触发，并只推送新增内容。

## 约束

- 禁止硬编码最终结果。
- 禁止购买第三方 API 绕过核心功能。
- 禁止写死 token、借用他人账号、突破访问控制。
- 禁止高频访问、攻击或造成 IP 封禁风险。
- 登录站点只做免费会员能看到的内容。

## 当前实现假设

- T0 优先保证非登录公开站点抓取、字段抽取、清洗去重和 Word 生成跑通。
- T1 再补第 3 来源、登录态站点、定时增量和风险预警。
- 如果登录态站点 1-2 小时仍不稳定，立即止损，保留非登录多源抓取与 Word 输出。
