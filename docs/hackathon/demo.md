# 赛题 1 演示脚本

## 演示主线

自然语言输入 -> 解析四要素 -> 抓取网站 -> 清洗去重 -> 生成 Word -> 展示 Word 内容。

## 推荐演示问题

```text
最近1个月安徽省区域内的服务器招标信息都有哪些。
2026年4月份北京充电桩相关的招标信息都有哪些。
最近3个月上海区域内的充电桩招标信息都有哪些，请汇总后每天9:00发送给我。
```

## 页面或 CLI 需要展示

- 用户原始问题。
- 解析结果：关键词、地区、时间范围、频率。
- 来源站点列表。
- 抓取进度和耗时。
- 结构化结果表：标题、发布时间、来源、链接、核心内容摘要、附件链接、风险提示。
- 去重结果：原始数量、去重后数量、过滤原因。
- Word 输出路径。
- 当前 Web 地址：`http://localhost:8081/`。

## 录屏检查点

- 输入一个自然语言问题。
- 系统自动解析四要素。
- 系统访问至少 1 个真实来源并抓取正文。
- 系统生成 `.docx` 文件。
- 打开 Word 文件，确认字段完整、内容可读、来源链接可追溯。
- 如果已经实现定时/增量，演示第二次运行不重复输出旧内容。

## 新增演示：Agent 模型 + 登录态 + 定时增量

推荐输入：

```text
最近3个月上海区域内的充电桩招标信息有哪些，请汇总后每天9:00发送给我，并优先查看需要登录后才能看到完整正文的来源。
```

演示顺序：

1. 首页展示“登录态/鉴权来源”和“定时增量任务”两个区域。
2. 如需演示登录态，点击登录来源的“手动登录并保存”，在 Playwright 浏览器里手动完成登录；系统保存 `data/login/jianyu-state.json` 或对应来源的 storageState 文件。
3. 提交推荐输入，展示 Agent 模型需求理解、全网搜索词、固定来源和登录来源调度过程。
4. 展示生成的 Word 报告，确认报告包含 Agent 摘要、搜索词、登录态说明、来源统计和公告明细。
5. 查看 `data/tasks.json`，确认每天 9:00 任务已保存。
6. 点击任务“手动执行”，展示第二次运行读取 `data/history/*.json`，重复公告被跳过，只输出新增公告。

## 页面讲解口径

- “官方评分检查”：先用这一排给评委过评分点，确认系统已经覆盖意图解析、多来源、登录态、清洗去重、Word、时效。
- “本次结果”：给评委看系统这次有没有找到新公告；如果没有新增，要解释为历史已见公告被过滤，证明增量不重复。
- “登录来源”：给评委看登录态/鉴权能力；先手动登录保存，再跑查询。
- “订阅提醒”：给评委解释定时增量，不要讲 `tasks.json`，只讲“每天 9 点自动检查，只把新增公告放进报告”。
- “系统理解”：给评委看 Agent 是否理解关键词、地区、时间和提醒频率。
- “来源概览”：只讲来源是否可用；技术诊断默认折叠，除非评委追问失败原因。

## 老板视角报告讲解

- Word 不讲技术过程，先讲“本次结果”：找到了几条新公告，或者没有新增且已过滤历史公告。
- 公告明细重点看“摘要、来源、参考价值、风险、链接”。
- 如果风险为“暂无明显风险”，说明系统没有识别到紧急截止/变更等需要立即处理的信息；不是没分析。
- 如果来源是“全网搜索”，话术是“这是候选线索，建议点开原文确认”；如果来源是公共资源/采购平台，话术是“可信度更高，可直接作为报告依据”。

## 登录态演示口径

1. 点击“打开剑鱼登录页”：普通浏览器新标签打开剑鱼页面，证明不是假按钮。
2. 点击“启动登录态采集窗口”：后端启动 Playwright 可见浏览器窗口，并导航到剑鱼页面；页面返回 captureId 后提示等待用户登录。
3. 在 Playwright 窗口中手动完成登录/验证码/扫码。
4. 回到页面点击“我已完成登录，保存登录态”：系统保存 `data/login/jianyu-state.json`。
5. 点击“检查登录态状态”：状态应变为“登录态已保存”。
6. 再执行查询：来源概览里剑鱼标讯会尝试使用登录态；如果失效，显示“登录态可能过期，请重新登录”，不阻断其他来源报告。

注意：演示时 8081 服务需要从正常交互式终端启动，不能用受限沙箱启动，否则后端可能没有权限弹出可见浏览器。当前修复已避免 Playwright 在点击按钮时临时下载浏览器包，成功启动后接口会返回 `success=true` 和 `captureId`。

## 2026-05-18 演示补充：有效公告与候选线索分层讲法

### 演示重点
- 先展示顶部指标：有效公告数、来源处理数、登录态状态、Word 状态。
- 再展示评分点检查：意图解析、来源处理、登录态、清洗去重、Word、耗时。
- 公告区分两类讲：
  - 有效公告：证据完整，可进入 Word 正文。
  - 候选线索：模型/搜索发现的可点击线索，但仍需打开原文核验，不写入 Word 正文。

### 推荐演示问题
```text
最近5个月北京服务器招标信息有哪些
最近3个月广东软件服务招标信息每天9:00发送
全国最近两个月耳机招标信息有哪些
```

### 讲解口径
- 如果有效公告为 0 但候选线索不为 0：
  - 说明系统已经找到可核验来源，但出于事实可信，没有把发布时间/正文证据不足的网页直接写进报告正文。
  - 候选线索可点击打开原文，适合作为人工复核入口。
- 如果来源健康有“已跳过/网络波动”：
  - 说明系统采用降级策略，单个来源失败不影响整体报告生成。
- 如果模型状态显示规则兜底：
  - 检查启动 Maven 的 PowerShell 是否设置了 `XFUSION_API_KEY`、`XFUSION_BASE_URL`、`XFUSION_MODEL=kimi-k2.6`。

### Word 演示
- Word 按“老板可读简报”讲：
  - 查询摘要
  - 本次结论
  - 建议优先查看
  - 全部相关公告
  - 来源说明
  - 订阅提醒
- 不讲技术堆栈；技术诊断只在前端折叠区查看。
