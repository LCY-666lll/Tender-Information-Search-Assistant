# 详设文档：招投标信息聚合工具

## 目标

系统面向赛题 1 的核心评分点设计，重点展示“自然语言问题 -> 多网站抓取 -> 清洗去重 -> 风险预警 -> Word 汇总”的完整链路。

## 架构

- `HomeController`：首页、查询提交、Word 下载。
- `IntentParser`：解析关键词、地区、时间范围、频率。
- `SourceCrawler`：统一来源接口，所有网站适配器输出统一 `BidItem`。
- `ConfigurablePublicCrawler`：基于配置的公开来源抓取器，支持失败 warning 和演示兜底。
- `CleanerDeduplicator`：过滤非目标内容，合并重复公告来源。
- `RiskAnalyzer`：识别截止临近、附件缺失、变更公告等风险。
- `HistoryService`：用本地 JSON 记录已输出条目，支持增量去重。
- `WordReportService`：生成 `.docx` 汇总报告。

## 多来源设计

当前 `application.yml` 配置 6 类来源：

- 全国公共资源交易平台。
- 中国政府采购网。
- 中国招标投标公共服务平台。
- 上海公共资源交易平台。
- 中国移动采购与招标网。
- 剑鱼标讯，作为登录态能力预留。

系统不绑定安徽或单一地区，地区由自然语言解析结果决定，并在清洗阶段过滤。

## 降级策略

外部网站有反爬、验证码、结构变化或网络不可用风险。系统采用来源级隔离：

- 单来源失败只写入 `SourceStatus.warning`。
- 其他来源继续执行。
- Word 仍生成，并在来源覆盖表中展示失败原因。
- 登录态来源未配置合法登录态时，不阻塞公开来源报告。

## 增量策略

系统根据地区、关键词和调度类型生成本地 history key，将已输出公告 itemId 写入 `data/history/*.json`。后续同一任务执行时，已出现过的 item 不再进入 Word 明细。

## 边界

- 当前版本不绕过验证码、不写死 token、不购买第三方 API。
- 登录态来源仅预留合法手动登录扩展点。
- 真实抓取结果受目标网站可用性影响，报告会保留 warning 供演示说明。
